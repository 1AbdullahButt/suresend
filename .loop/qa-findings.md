## Findings
- [severity: minor] components/agent/CheckView.tsx:47-55 · expected: the number and the list it opens to tell one consistent story · actual: the count is held sends while the list holds every flagged check. Repro: Léa → Docs → Doc settings → Remove from this demo → "Double-check / Matches today, changing soon" → tick "I've checked…" → Send anyway → the sent card reads "Wrong replies stopped today **0**", and opening it shows one row, "Double-check · Léa K. · Matches today, changing soon", with Correct catch / False alarm, for a reply that was neither wrong nor stopped (screenshot `scratchpad/qa/shots/mismatch-1440.png`). The brief asked for "the same list as Demo menu → Review flagged replies" and D-065 records the trade-off, so it isn't blocking. Suggest a caption over the list ("Flagged this session: N, M held") or a per-row status ("Held" / "Sent with your OK") · SPEC §11 (metrics: intercepts = blocked HOLD/ESCALATE sends)
- [severity: minor] lib/client/outcome.ts:276-290 (`flagReason`) · expected: the one-line reason explains the verdict · actual: on two Double-check paths the line reads like a plain contradiction and drops why it's only a Double-check. B7 (the guided tour's step-5 edit, WEAK_BASIS) → "Instant transfer: docs say 2 business days, reply said 4", while the card's headline is "The doc behind this changed". fee-hedged (HEDGED_CONTRADICTION) → "Fee: docs say refunded, reply said not refunded", but the reply said "probably isn't refunded". Both are factually right; the hedge and the weak basis are lost. All other lines are clear and consistent: "Instant transfer: docs say 1 business day, reply said 4", "Instant transfer fee: docs say not refunded, reply said refunded", "Depends on the transfer", "Your docs disagree", "Missing an answer", "Your reply is vague on this", "Outside what we can check", "Matches today, changing soon"
- [severity: minor] components/shell/App.tsx:71-72 and lib/client/useSureSend.ts:75 (`RESET_TOAST`) · expected: the confirm dialog to say what Reset now discards · actual: Reset now also throws away typed but unsent drafts, sent messages, results, persona and selection (the point of item 1), but the dialog still says only "Restores every seed doc (N edited) and clears this browser's numbers." and the toast says "seed docs restored and this browser's numbers cleared". Before this round, drafts survived until a reload. A visitor with a half-typed reply loses it with no warning
- [severity: minor] components/inbox/ChatCard.tsx:83-86 · expected: the element "Open conversation with Lukas R." lands on to say which conversation it is · actual: focus goes to `<h1 tabIndex=-1>Failed transfer</h1>`, which is the same text on every ticket, so a screen reader announces "Failed transfer, heading level 1" with no customer name. The name is in a sibling span. Suggest `aria-describedby` pointing at the customer name, or the name inside the heading's accessible name
- [severity: minor] lib/client/useSureSend.ts:320-360, 122-128 · latent, not reproduced: Reset aborts an in-flight check but not an in-flight Send (`postSend` takes no signal), and `updateMetrics` writes storage from inside a state updater. With `/api/send` delayed past a Reset, React 19 dropped the old tree's updates, and storage stayed clear, before and after a reload (probe above). Nothing leaks today, but that depends on React's behaviour for unmounted components. A mounted ref or an AbortController on `send` would make it explicit
